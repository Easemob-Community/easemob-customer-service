# 07 · 部署、运维与测试

## 1. 环境规划

| 环境 | 用途 | 配置 |
|------|------|------|
| dev | 开发联调 | 单机 Docker Compose；环信沙箱 AppKey；AI 厂家测试 Key |
| staging | 预发验收 | 与生产同构（可缩容）；环信正式 AppKey 独立开关 |
| prod | 生产 | service ≥ 2 副本；MySQL 主从；Redis 哨兵/集群 |

### Docker Compose（dev 示例）

```yaml
version: "3.8"
services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: customer_service
    ports: ["3306:3306"]
    volumes:
      - ./easemob-customer-docs/sql/init-schema.sql:/docker-entrypoint-initdb.d/init-schema.sql

  redis:
    image: redis:7
    ports: ["6379:6379"]

  service:
    build: ./easemob-customer-service                 # 【现状：各模块 Dockerfile 待补充，当前以本地 mvn 打包后 java -jar 运行】
    environment:
      SPRING_PROFILES_ACTIVE: dev
      EASEMOB_CLIENT_ID: ${EASEMOB_CLIENT_ID}
      EASEMOB_CLIENT_SECRET: ${EASEMOB_CLIENT_SECRET}
    ports: ["8080:8080"]
    depends_on: [mysql, redis]

  web:                        # 访客端 H5
    build: ./easemob-customer-web
    ports: ["8081:80"]

  console:                    # 控制台
    build: ./easemob-customer-console
    ports: ["8082:80"]
```

## 2. Nginx 参考配置

```nginx
server {
  listen 443 ssl;
  server_name cs.example.com;

  location /api/       { proxy_pass http://service:8080/; }      # open/admin/callback
  location /console/   { proxy_pass http://console:80/;  }
  location /           { proxy_pass http://web:80/;      }        # 访客端
}
```

> 回调地址在环信控制台配置为 `https://cs.example.com/api/easemob/callback/message`（务必 HTTPS + 验签）。

## 3. CI/CD（GitLab CI 示例）

```yaml
stages: [test, build, deploy]

test-service:
  stage: test
  script: cd easemob-customer-service && mvn -q test

build:
  stage: build
  script:
    - docker build -t registry/cs-service:$CI_COMMIT_SHORT_SHA easemob-customer-service
    - docker build -t registry/cs-web:$CI_COMMIT_SHORT_SHA     easemob-customer-web
    - docker build -t registry/cs-console:$CI_COMMIT_SHORT_SHA easemob-customer-console

deploy-prod:
  stage: deploy
  when: manual
  script: kubectl set image deploy/cs-service service=registry/cs-service:$CI_COMMIT_SHORT_SHA
```

前端构建以 `--dart-define`（Flutter）/ `.env.production`（Vue）注入环境差异；密钥全部走 CI 变量/K8s Secret。

## 4. 监控与告警

| 监控项 | 指标 | 告警阈值 |
|--------|------|----------|
| 服务健康 | /actuator/health、实例存活 | 存活实例 < 2 |
| 回调处理 | 耗时 P95、失败率、队列积压 | P95>300ms 或积压>500 |
| AI 调用 | 成功率、failover 次数、平均耗时 | 成功率 <95%（5min） |
| 转人工 | 转人工率、排队人数、抢单时长 | 排队 >30 人 |
| 环信连通 | Token 刷新失败、REST 4xx/5xx | 连续 3 次失败 |
| 资源 | JVM、线程池水位、DB/Redis | 线程池队列 >80% |

- 链路：traceId 贯穿 open-api → 回调 → AI → 环信发送，日志按 traceId 聚合；
- 指标：Micrometer → Prometheus → Grafana 看板（会话量/AI 解决率实时大盘）。

## 5. 测试方案

### 5.1 测试金字塔

| 层 | 范围 | 工具 |
|----|------|------|
| 单元 | 策略计算、词表匹配、状态机迁移、AES/签名工具 | JUnit5 + Mockito（≥70% 核心覆盖） |
| 集成 | 建群/发消息（环信 mock server）、回调全链路、MySQL/Redis Testcontainers | Spring Boot Test |
| 端到端 | 发起会话→AI 应答→转人工→评价 全链路 | Postman/Newman + 环信沙箱 |

### 5.2 关键用例（必须全绿）

| # | 用例 | 预期 |
|---|------|------|
| 1 | 新用户发起会话 | 群组创建、AI 入群、欢迎语、状态 AI_SERVING |
| 2 | 同一用户重复 start | 复用原会话，不重复建群 |
| 3 | 用户发消息 → AI 正常回复 | ④⑤⑥ 闭环，消息落库 |
| 4 | AI 超时（mock 超过厂家超时配置） | failover 备厂家；双失败 → 兜底话术 + failCount+1 |
| 5 | 连续 2 次 AI 失败 | 自动转人工流程启动 |
| 6 | 用户发「转人工」 | 关键词命中 → 分配 → 坐席入群 → 系统提示 |
| 7 | 平均分配 | 负载最低坐席命中；满员坐席被跳过 |
| 8 | 熟客优先 | 有效期内熟客在线 → 命中；离线 → 降级平均 |
| 9 | 指定 ID | 命中指定坐席；不可用 → 排队/降级 |
| 10 | 无坐席 | 排队话术 + 位置正确；坐席上线后 FIFO 补位 |
| 11 | 重复回调（同 msgId ×3） | 只处理一次 |
| 12 | 并发转人工（同用户 10 并发） | 仅 1 次成功分配 |
| 13 | 会话 30min 无消息 | 自动关闭 + 负载释放 |
| 14 | 评价提交 | cs_evaluate 落库，重复提交幂等 |
| 15 | 回调验签失败 | 401 拒绝，不进入业务【现状：验签未实现，仅按 msgId 幂等】 |

> 用例 3 补充：用户消息经「环信回调 + `/open/message/record`」双通道触发 AI，服务端 10s 内容去重保证只应答一次；已关闭会话再次发消息返回 4002。
> 用例 13 补充：会话关闭（主动/超时/坐席结束）后发送结束语（`ext.bizType=CLOSED`）并解散环信群组。

### 5.3 性能压测（JMeter）

| 场景 | 并发 | 目标 |
|------|------|------|
