# 01 · 产品设计与业务流程

## 1. 业务角色与账号体系

系统中的所有「发言人」都是环信用户，由自建后端的**账号服务**统一维护，分为三组：

| 组别 | 说明 | 环信侧 | 示例 |
|------|------|--------|------|
| **AI 组** | AI 客服账号池，可按技能/业务线划分（A 组、B 组…） | 注册为环信用户，由后端持有 Token 代发消息 | `ai_bot_001`、`ai_bot_finance_01` |
| **用户组** | 访客/客户账号池（用户 ID:1、ID:2…），可按来源/渠道分组 | 客户端用环信 SDK 登录 | `user_10001` |
| **坐席组** | 真人客服账号池，隶属 A 组 / B 组等技能组，有在线状态与接待上限 | 控制台坐席端用环信 SDK 登录 | `agent_1001` |

> 设计要点：AI 与真人坐席在 IM 层面完全同构（都是环信账号），「谁正在服务」由会话表中的 `current_handler_type`（AI / HUMAN）决定，切换无需重建群组。

## 2. 核心业务流程总览（对应产品图）

### 2.1 主链路（顶部实线）

```
开始 → 用户点击客服入口 → 创建群组会话 → 获取AI账号，AI进行回复
     → 获取真人账号，真人取代AI回复 → 发送消息（持续对话）
```

### 2.2 九大步骤时序（① ~ ⑨）

**阶段一：发起会话 + AI 接待（①②④⑤⑥）**

```
访客端/Web/App                自建后端                       环信                  AI厂家
    │  点击客服入口              │                            │                     │
    │ ────────────────────────▶ │ POST /open/session/start   │                     │
    │                           │ ① 账号服务取 AI 组在线账号    │                     │
    │                           │ ─────────────────────────▶ │ 创建群组(用户+AI)    │
    │  ◀─────────────────────── │ 返回 groupId/AI 账号/凭证    │                     │
    │  ② SDK 登录环信，收发消息   │                            │                     │
    │ ◀═══════════════════════════════════════════════════▶  │                     │
    │  用户发消息                │                            │                     │
    │ ═════════════════════════▶│（SDK 直发环信 + POST /open/message/record 落库）│
    │                           │  ◀── 消息回调(发送后回调) ── │                     │
    │                           │ ④ 消息接收服务（回调与 record 双通道触发，│                     │
    │                           │    10s 内容去重）→ AI 厂家 ─────────────────────▶│
    │                           │ ⑤ 返回答案 ◀─────────────────────────────────────  │
    │                           │ ⑥ 发送消息服务(AI账号身份) ─▶│ 群发消息            │
    │  ◀═══════════════════════ 用户收到消息 ═════════════════ │                     │
```

**阶段二：转人工（③⑦⑧⑨）**

```
  用户发"转人工"/AI置信度低/命中关键词
    │                           │ ③ 环信回调服务触发消息回调
    │                           │    转人工判定引擎命中
    │                           │ ⑦ 分配服务启动：获取用户ID(坐席ID)
    │                           │ ⑧ 分配服务 ↔ 账号服务：
    │                           │     读取用户组/熟客关系/坐席在线态/负载
    │                           │     按策略计算：平均分配 | 熟客优先 | 指定ID
    │                           │ ⑨ 返回用户ID(真人坐席账号)
    │                           │ ─────────────────────────▶ 环信：坐席加入群组
    │                           │ 更新会话 current_handler_type=HUMAN
    │                           │ 系统消息："客服 xxx 为您服务"（AI 停止回复）
    │  ◀═══════════════════════ 后续消息直达坐席工作台 ══════
```

### 2.3 转人工触发规则（可配置）

| 触发方式 | 说明 | 优先级 |
|----------|------|--------|
| 用户显式请求 | 命中关键词：「转人工」「人工客服」「投诉」等（词表可配） | 高 |
| AI 主动转接 | AI 厂家返回 `transfer=true` 或置信度低于阈值 | 高 |
| 失败兜底 | AI 连续 N 次（默认 2）未命中/超时/报错 | 中 |
| 业务规则 | 指定业务线/VIP 用户直接进入人工队列 | 中 |
| 坐席主动接入 | 坐席工作台从等待队列抢单 / 管理员指派 | 低 |

### 2.4 会话状态机

```
              startSession                      转人工命中
  [CREATED] ──────────────▶ [AI_SERVING] ─────────────────▶ [HUMAN_SERVING]
                                │    ▲                            │
                                │    │ 人工离线/转回AI(可选)        │ close
                                │    └────────────────────────────┤
                                ▼ close                           ▼
                            [CLOSED] ◀──────── 超时自动关闭/用户结束/坐席结束
                                │
                                ▼ 满意度评价(可选)
                          [EVALUATED]
```

| 状态 | 含义 | 进入条件 |
|------|------|----------|
| CREATED | 群组已建，待 AI 首响 | startSession 成功 |
| AI_SERVING | AI 服务中 | AI 账号入群成功 |
| HUMAN_SERVING | 人工服务中 | 分配成功且坐席入群 |
| CLOSED | 已关闭 | 主动结束 / 超时（默认 30min 无消息）；关闭时发送结束语（`ext.bizType=CLOSED`）并**解散环信群组**，访客端进入「会话已结束」态 |
| EVALUATED | 已评价 | 用户提交满意度 |

## 3. 分配策略详细设计（分配服务）

### 3.1 策略矩阵

| 策略 | 算法 | 适用场景 |
|------|------|----------|
| **平均分配** | 在「在线且未达接待上限」的坐席中取当前接待数最少者；相同则按最近派单时间轮转（Redis 有序集合维护负载） | 通用默认 |
| **熟客优先** | 查熟客关系表（用户 ↔ 上次服务坐席，有效期内），若该坐席在线且未满员则优先命中；否则降级为平均分配 | 提升连续性体验 |
| **指定 ID** | 按业务方传入或规则引擎输出的坐席 ID 直接指派；目标不可用时进入等待队列或降级 | VIP 专属客服 |

### 3.2 分配决策流程

```
转人工请求(userId, groupHint, specifyId?)
   │
   ├─ specifyId 非空 ──▶ 指定ID策略 ──▶ 可用? ─是─▶ 返回该坐席
   │                                    └否▶ 入等待队列/降级平均
   ├─ 查熟客关系(valid) ─▶ 熟客在线 && 负载<上限 ─是─▶ 返回熟客坐席
   │                                    └否▶ 降级平均分配
   └─ 平均分配：过滤(在线 && 技能组匹配 && 负载<上限)
          ├─ 候选非空 ─▶ 取负载最低者，Redis 原子 +1，写熟客关系
          └─ 候选为空 ─▶ 进入排队(队列位置提示用户) / 留言模式
```

### 3.3 排队与溢出

- 无可用坐席时：会话保持 `AI_SERVING`（AI 兜底）+ 回复排队话术，同时写入排队表；
- 坐席上线/释放容量时触发「队列消费」，按入队时间 FIFO 补位；
- 超过排队上限（可配，默认 50）转为留言模式（消息落库，坐席次日处理）。

## 4. AI 编排设计

### 4.1 AI 厂家配置（多厂家可插拔）

每个 AI 厂家一条配置：

| 字段 | 说明 |
|------|------|
| providerCode | 厂家编码，如 `OPENAI` / `DIFY` / `COZE` / `SELF_NLP` |
| baseUrl / appKey / appSecret | 接口地址与凭据 |
| timeoutMs / retryTimes | 超时与重试 |
| weight / status | 灰度权重、启停 |
| extraJson | 厂家特有参数（model、temperature 等） |

- **发送消息服务**（→AI）：按 providerCode 路由到对应 `AiProviderAdapter`，统一请求模型 `{sessionId, userId, question, history}`；
- **消息接收服务**（←AI）：统一响应模型 `{answer, confidence, transfer, suggestQuestions[]}`；
- 支持主备切换：主厂家超时/失败自动failover 到备用厂家。

### 4.2 AI 应答流水线（步骤④⑤⑥）

```
用户消息入库（环信回调 与 /open/message/record 双通道，10s 内容去重）
  → 会话状态检查(仅 AI_SERVING 才发 AI；已关闭会话拒写 4002)
  → 组装上下文(最近 N 条消息, N 可配默认 10)
  → 调用 AI 厂家(超时/重试按厂家配置, failover 到备厂家)
  → 响应解释：
      transfer=true ─▶ 转人工流程
      answer 非空  ─▶ 环信发送(AI 账号) + 落库
      空/失败      ─▶ failCount+1，达阈值转人工，否则兜底话术
```

## 5. 功能清单（PRD 摘要）

### 5.1 访客端（Web Widget / App）

| 模块 | 功能 |
|------|------|
| 入口 | 悬浮按钮、未读角标、在线状态提示（AI/人工） |
| 会话 | 发起/恢复会话（服务端幂等复用） |
| 消息 | 文本、图片、表情、文件；发送中/失败重发；已读回执 |
| 转人工 | 关键词触发 + 输入框上方「转人工」按钮；排队位置提示 |
| 评价 | 会话结束弹满意度（1-5 星 + 标签 + 文本） |
| 其他 | 常见问题引导、欢迎语、输入中状态 |

### 5.2 管理控制台

| 模块 | 功能 |
|------|------|
| 坐席工作台 | 会话列表（我的/等待队列）、多会话并发窗口、快捷回复、内部备注、转接其他坐席/组、结束会话、用户资料侧栏 |
| 账号管理 | AI 组/用户组/坐席组的 CRUD，坐席技能组、接待上限、上下线 |
| 分配策略 | 全局默认策略 + 按渠道/技能组覆盖；熟客有效期；排队参数 |
| AI 管理 | 厂家配置 CRUD、连通性测试、灰度权重、转人工词表、兜底话术、上下文长度 |
| 数据看板 | 会话量、AI 解决率、转人工率、平均响应时长、满意度、坐席负载排行 |
| 系统 | 角色权限（管理员/组长/坐席）、操作日志、环信 AppKey 配置 |

### 5.3 服务端能力清单

开放接口（访客）、管理接口（控制台）、环信回调接口、AI 适配 SPI、定时任务（超时关会话、队列消费、统计聚合）。

## 6. 非功能性要求

| 项 | 指标 |
|----|------|
| 性能 | 发起会话 P95 < 500ms；AI 首响 P95 < 3s；回调处理 P95 < 300ms |
| 可用性 | 自建后端无状态多副本；环信/AI 故障时降级（提示 + 留言） |
| 一致性 | 消息幂等（msgId 唯一约束）；分配并发用 Redis 分布式锁 |
| 安全 | 接口签名/Token；凭据加密存储（AES）；敏感操作审计 |
| 可观测 | 全链路 traceId；AI 调用与转人工事件指标化 |
